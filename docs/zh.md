# Mod Manager — 模组、游戏及其文档

Mod Manager 是主菜单中的**模组与合集**屏幕。在这里可以查看装了哪些模组、了解每个模组的用途、从在线目录安装或更新模组、停用模组，也可以翻看现成游戏的内部构成，弄清它们由哪些模组搭建。

它属于随菜单一起始终加载的外壳，因此在启动任何游戏之前就能使用。

## 打开方式

在主菜单选择**模组与合集**。该屏幕有两个标签页：

- **模组** — 游戏认识的所有模组：已安装的和目录提供的。
- **合集** — 现成的游戏，以及每款游戏由哪些模组搭成的结构。

**← 菜单**返回主菜单。右上角的 **？** 按钮，或按 **F1**，开启上下文提示：把鼠标悬停在控件上看它的作用，点击可固定提示，按 **Esc** 退出。

## 浏览模组

![模组标签页：左侧是筛选器，中间是带封面图的模组卡片网格，搜索框旁开着提示，还有排序和 Refresh catalog 按钮。](assets/mods-list.jpg)

每张卡片显示模组的封面、标题、作者、来源目录、有多少游戏在用它（**在 4 个合集中**）、状态与版本，以及一个开关。

- **搜索模组...** 按标题、作者或标识符过滤。
- **按名称 / 按作者 / 按状态** 调整列表排序。
- 左侧的**筛选**按**状态**（未安装、已安装、有可用更新、有旧版本可用、本地已修改、已停用）和**分类**（例如剧情、玩法、视觉、音频、库、引擎、工具）收窄列表。**重置**清除筛选和搜索。
- **刷新目录**下载当前已发布模组的列表。

*本地已修改*表示已安装的文件与目录上同一版本的副本不一致——例如你正在自己改动的模组。

## 查看模组介绍

点击卡片打开它的页面：封面、版本选择器、各种操作、来自 manifest 的简短描述，以及模组提供时的**文档**——一份像这样的完整指南。

![一个模组页面：Audio Engine 的封面和版本、Reinstall 和 Disable 按钮、“in 4 collections”、描述，以及带语言选择器的 Documentation 区块。](assets/mod-page.jpg)

文档是**已安装**版本的指南。如果在版本选择器里选了别的版本，提示会提醒你：下面的指南仍属于已安装的那一版。

**文档语言。** 文档标题右侧的选择器默认为**自动 · 界面语言**：指南跟随游戏界面语言。若模组没有该语言的指南，管理器会先显示模组的默认指南，再退回英文，最后退回第一份可用的指南；指南上方一行会标明实际显示的语言（例如 `EN`）。你也可以自己在选择器里挑语言。没有任何指南的模组会继续显示 manifest 描述。

给模组作者：把指南放进 `docs/en.md`（译文放 `docs/<语言>.md`，或 `docs/default.md`），图片放在旁边，例如 `docs/assets/screen.png`，以 `assets/screen.png` 引用。查看器支持标题、段落、列表、引用、代码块、链接和 PNG/JPEG/WebP 图片；不会运行 HTML、表格或动画。

## 安装、更新、停用、删除

模组页面上的按钮和卡片上的开关：

- **安装 / 更新 / 降级 / 重新安装**把所选版本从目录下载到你的用户目录（`user://mods/`）。
- **停用 / 启用**（或卡片上的开关）决定模组是否被加载。停用的模组保留文件和存档中的数据。
- **删除**在确认后移除一个下载来的模组。

任何一项操作之后都会出现横幅：**重启游戏后更改才会生效**。Mod Manager 自己无法在自己的屏幕上被删除或停用。

**已安装不等于在用。** 游戏只加载它合集里列出的模组，外加菜单外壳。安装只是让模组可用；只有当游戏的合集包含它时，它才会进入游戏。

## 游戏与合集

**合集**标签页首先展示现成的游戏。游戏就是一个*合集*：一组有名字的模组，加上起始地点。

![游戏画廊：Cthangover、My Novel 和 RPG Plus 的卡片，均显示“Ready to play”，模组计数 32/32、11/11、36/36，以及 Edit scheme 按钮。](assets/games-gallery.jpg)

卡片会告诉你游戏需要的东西是否都装齐了（**可以开始游戏**，或**缺少 N** / **安装（N）** / **启用（N）**）。一个按钮即可安装或启用缺失内容。**编辑结构**打开游戏的内部构造；**＋ 打造你自己的游戏**从新建合集开始。

### 游戏的结构

![My Novel 的结构：Story、Assets 和 2D engine 区块及其模组，从每条依赖指向需要它的模组的箭头，以及显示 My Novel 版本要求的检查器。](assets/collection-scheme.jpg)

结构图展示游戏的*机制*（诸如 Story、Assets、2D engine 的区块）和其中的模组。箭头从依赖指向需要它的模组。卡片位置和区块只是用于阅读：它们不决定加载顺序。

选中一个区块或模组，它就会出现在**检查器**里。在那里可以修改游戏要求的版本：**任意版本**、**不低于**、**精确版本**、**版本分支**（`^1` 接受任何 1.x）等。这是游戏的要求，不是你已安装的版本。**检查**列出问题；**计划**显示应用该合集会安装或启用什么。

![一个模组的检查器，其要求“Exactly 999.0.0”与已安装的 1.0.0 不符：要求和已安装版本都标红。](assets/version-mismatch.jpg)

结构图的其他按钮：**+ 机制**和**添加模组**修改游戏，**复制**生成你自己的副本（并提议一并复制存档），**JSON**显示原始定义，**保存**和**重置**保留或放弃更改，**应用合集**安装并启用计划中列出的内容。改过的内置游戏可用**恢复内置版本**还原；存档保留。

对游戏的更改在下次启动时生效。游戏的存档在模组变动后依然可用：离开游戏的模组数据被单独保存，随模组回归。

## 出现问题时

1. **某个模组没有进入游戏。** 检查它是否已启用、游戏的合集是否包含它（打开**编辑结构**）。
2. **“安装失败”。** 检查网络连接，再点一次**刷新目录**。
3. **游戏卡片显示缺少或有 问题。** 打开它的结构和**检查**标签页：里面列出缺失的模组、版本差距和冲突。
4. **目录冲突。** 同一模组同一版本被两个目录以不同内容发布；相信你信任的那个目录。
5. **没有文档区。** 该模组还没有 `docs/` 指南；此时显示的是 manifest 描述。
